# SpineAlign Lite

**A dual-IMU wearable posture-monitoring prototype with an ESP32/Wokwi simulation.**

SpineAlign Lite reads two MPU6050 motion sensors—one representing the neck and one representing the back—on an ESP32. Each sensor has an independent angle/gyroscope-bias Kalman filter. The firmware compares both calibrated angles against posture thresholds, waits for sustained deviation before the first alert, applies hysteresis after an alert, and displays the live angles and status on an SSD1306 OLED.

> **Scope:** This repository contains the Wokwi/ESP32 simulation firmware and Markdown versions of the supplied project documentation. The intended Bluetooth companion app/link, battery/charging circuit, physical haptic motor, and finished wearable are not implemented here. The simulation uses an LED instead of a haptic motor and adds an OLED for demonstration.

## Hardware in the simulation

| Component | Connection / setting |
|---|---|
| ESP32 DevKit-C V4 | Main controller |
| Neck MPU6050 | I²C address `0x68`; AD0 to GND |
| Back MPU6050 | I²C address `0x69`; AD0 to 3V3 |
| Sensors and OLED | SDA = GPIO 21, SCL = GPIO 23; common 3V3 and GND |
| SSD1306 OLED | I²C address `0x3C` |
| Status LED | GPIO 25 to LED anode; cathode to GND |
| Calibration pushbutton | GPIO 14 to GND; firmware uses `INPUT_PULLUP` |

The two MPU6050s share the I²C bus; their different AD0 connections give them distinct addresses. Verify the address arrangement against any physical boards before reproducing the circuit.

## Dependencies

The sketch uses the ESP32 Arduino core, Adafruit GFX Library, and Adafruit SSD1306. `Wire` and `math.h` are provided by the Arduino/ESP32 environment.

## Build locally

Install Arduino CLI. Then run the following from the repository root:

```sh
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32
arduino-cli lib install "Adafruit GFX Library" "Adafruit SSD1306"
arduino-cli compile --fqbn esp32:esp32:esp32 --output-dir build .
```

The `wokwi.toml` file points to the firmware binary and ELF generated by the build. In Wokwi for VS Code, open this repository as the workspace, compile first, and then start the simulator. The original online Wokwi project has its own build environment and does not need this local output configuration.

## Demo walkthrough

1. Start the simulation and check the serial monitor for successful neck and back sensor initialization.
2. Place both simulated sensors in the reference position.
3. Press the calibration button or type `CALIBRATE` in the serial monitor and press Enter.
4. Tilt either sensor past the 15° trigger threshold and keep the deviation there for 3 seconds.
5. Observe the first double LED pulse and the OLED `ALERT` status.
6. Recovery after the first alert requires both measured deviations to be below 12°. A lighter LED pulse repeats every 45 seconds while poor posture continues.
7. Use the serial telemetry to watch the live neck/back angles and alert state.

## Firmware behavior and limitations

- Calibration sets the current angle as the reference for the current session; it is not saved across reboots.
- If either sensor read fails, posture decisions pause and any active LED pattern is cleared to prevent stale angles from driving alerts.
- Angles depend on sensor orientation and mounting. The simulated axes may not match the physical wearable's axes without adjustment.
- Thresholds and filter settings are fixed in firmware and need validation on the real hardware.
- This is a course-project prototype, not a medical diagnostic device.

## Web dashboard

A simple responsive posture dashboard is included in `index.html`, `styles.css`, and `app.js`. It shows the current neck and back angle deviations, a good/needs-attention status, a recent angle-history chart, connection state, and a preview of the planned two-sensor 3D view.

- [Open dashboard source](index.html)
- [Dashboard setup and serial protocol](docs/Dashboard_Setup.md)
- [GitHub Pages deployment workflow](.github/workflows/pages.yml)

The dashboard starts in demo mode. For live readings, it connects to the current ESP32 firmware over USB serial at 115200 baud and reads lines such as `N:5.2,B:8.7,ALERT:0`. The `CALIBRATE` command can be sent from the dashboard. Live USB serial requires a desktop Chromium browser on HTTPS or localhost.

The 3D model and Bluetooth/Android integration are future work; the current browser dashboard does not claim those features are implemented.
